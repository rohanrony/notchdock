Agent Control: supported coding-agent providers and capability tiers

NotchDock Agent Control brings 19 coding-agent connectors into one compact monitoring surface. The key is to understand the capability tier for each provider: visibility does not imply permission control.

Native approve and deny

Claude Code, Codex CLI, and GitHub Copilot CLI expose native approval requests that Agent Control can present for approval or denial. Claude Code also supports multi-choice question answers and structured plan review with feedback. Each path depends on the provider’s own request transport.

Veto-only

Cursor and Gemini CLI provide session visibility and a safety stop. This is veto-only behavior; it is not a native approval flow that lets NotchDock grant a requested action.

Observation and handoff

Qwen Code, OpenCode, Amp, Cline, goose, Aider, Google Antigravity, Claude Cowork, Grok CLI, and DeepSeek Deep Code provide observational status or handoff to their own app or terminal. Antigravity has verified terminal control and question choices, but remains in the observational tier.

Remote and cloud connectors

Cursor Cloud, Devin, Codex Cloud, and SSH Host provide remote run monitoring and handoff. Depending on the connection, handoff opens a web page or an SSH session. These integrations do not become local native approval surfaces just because their activity appears in the tray.

All 19 connectors

The supported set is Claude Code, Codex CLI, GitHub Copilot CLI, Cursor, Gemini CLI, Qwen Code, OpenCode, Amp, Cline, goose, Aider, Google Antigravity, Claude Cowork, Cursor Cloud, Devin, Codex Cloud, SSH Host, Grok CLI, and DeepSeek Deep Code.

Choose based on the workflow

Use the tier labels to decide whether you want a compact status view, an explicit provider approval card, a safety stop, or a quick return to the agent’s actual workspace. Review the Agent Control feature page for the capability table and the privacy and permissions guide before enabling remote connections.
